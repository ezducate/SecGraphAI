# Security policy

## Supported versions

Security updates are provided for the newest release-candidate or stable minor release.

## Reporting a vulnerability

Do not open a public issue. Use GitHub private vulnerability reporting in the project
repository and include reproduction steps, impact, and affected versions. Maintainers
will acknowledge a report within five business days and coordinate disclosure and a fix.

GitHub private vulnerability reporting is the preferred encrypted transport. If it is
unavailable, open a minimal issue requesting a private maintainer contact without
including vulnerability details. Triage targets are five business days for acknowledgement,
ten business days for an initial severity assessment, and coordinated disclosure after a
fix is available. Supported reports receive credit unless anonymity is requested.

Never include live credentials, customer data, or unauthorized test results. Testing
must remain within systems you own or are explicitly authorized to assess.
